# Agent 长程失败的诊断与修复模板

> 以 2026-11-05 的检索 agent 漏召事件为标本提炼（10 个漏召金标 → 四类病因
> → 五项修复 → 六臂消融），供任何 agent 在"长程运行、结果可疑"时套用。
> 文献锚点见文末；所有数字都来自当天的可复跑测量（`tools/` 下有 harness）。

## 0. 何时套用本模板

出现下列任一症状，且你（agent）还想不通原因时：

- 结果"看起来很好"但交叉验证说不通：候选很多、佐证很少（isolated 查询）
- 空结果与"满结果"并存：同主题的查询有的 empty 有的爆满
- 反复优化下游（深度/阈值/排序）没有改善——病不在下游
- 长程任务中途产物质量莫名劣化，找不到是哪一步引入的
- 外部调用方超时/杀进程，工作丢失（无反馈的长操作）

## 1. 核心问题模型：开环表征的三重缺陷

```
任务(问句) ──[一次性变换]──> 内部表征(理解+词汇) ──> 下游所有机制复用它
                ↑                        ↓
            无环境接触              HyDE/融合/排序/分带…
            无任何验证              全部继承同一份未验证先验
```

| # | 缺陷 | 机制 | 当天实例 |
|---|---|---|---|
| 1 | **开环表征** | 任务→表征的变换发生在接触环境之前，纯凭先验，无验证环节 | 规划器把 "various languages" 读成 quantization，连续两代同源误读 |
| 2 | **错误继承** | 下游每个机制复用同一份表征——表面上 7 个家族"多元"，实际上表征零多元，一个上游错误→N 个相关失败 | planned/HyDE/pivot 三层全部复述问句词汇；唯二表征无关的通道（引文图/标题索引）一个需要种子、一个依赖索引覆盖 |
| 3 | **静默失败** | 世界总会回答点什么——空结果可见，**错误分布不可见**，置信度无下降信号 | 错词查询照样返回 1050 条"看起来很好"的候选 |
| +  | **因果距离** | 最终失败的病因在好几步之前，局部优化够不着 | 漏召的病因在规划层，加深/调阈值/改排序全部无效；LongRCA 实测：根因步距任务结束中位数 48 步，最强基线根因定位准确率仅 13.2% |

**MCP 超时事件是同一结构的第二实例**：客户端在 30s 内收不到任何反馈
（长操作的中间状态不可见）→ 杀调用 → 连带杀死已启动的后台任务。
修复与检索侧同构：早反馈（20s 内返回 job_id）+ 轮询代替阻塞。

## 2. 五步诊断流程（当天实际走过的路）

1. **建立上界（oracle test）**：假装拥有完美信息，问"环境到底能不能答？"
   - 检索实例：用 gold 自己的标题词反查 → 9/10 rank 1 ⇒ 索引无辜，病在表征
   - 反例：q1 连 oracle 都 MISS → by-DOI 直查为空 ⇒ **记录根本不在索引里**，表征无罪
   - MCP 实例：curl 直连端点秒通 ⇒ 网络无辜，病在 GCM 不读代理配置
2. **表征接地检查**：你的查询词汇与返回结果的词汇差多远？
   - 变体-gold 词重叠（0-3/10 ⇒ 词汇鸿沟）；结果集间 Jaccard 佐证（全 0 ⇒ isolated，盲打特征）
3. **通道隔离**：换一种**机制**（不是换深度）再试——哪个机制工作，哪个机制就指向病因
   - 标题索引 rank1 + 关键词 MISS ⇒ 词汇病；relevance search rank1 + title.search MISS ⇒ 端点形态病；引文链零交集 ⇒ 缺种子
4. **病因分类**（下表）：用 1-3 的证据把失败放进唯一的格子
5. **修复匹配**：每类病因有对应修复——修表征、修机制、修覆盖、修深度，或升级人工。**修完必须消融复测**（同尺 Before/After），否则不知道修没修对

## 3. 病因分类表

| 病因类 | 症状 | 判别试验 | 修复 | 当天实测 |
|---|---|---|---|---|
| **A. 表征错误**（词汇错配/方向误读） | oracle rank1 但查询词重叠≤3/10；查询 isolated | oracle test + 词重叠分析 | 语域阶梯重拟（问句词→行话→方法名→任务名）；机械 pivot 从佐证结果买词 | ladder+pivot 3/10（q3/q4/q10） |
| **B. 排名差一点** | 词对了（重叠 5+/10），gold 在 rank 15-40 | oracle test + wave 排名检查 | 加深/加变体/pivot 第二波 | q7@34 q8@18 q10@18 |
| **C. 端点形态不匹配** | 词全对但某源死活不出；换端点形态立即 rank1 | 同词换通道（title.search vs relevance search vs 引文图） | 增加机制多元的通道（relevance-search 候选） | q12/q13：/works?search= rank1 而 title.search MISS |
| **D. 覆盖缺口** | 连 oracle 都 MISS | by-DOI/by-id 直查 | 换有该记录的源（q1 在 S2 有、OpenAlex 无 ⇒ 探针加 S2 备胎）；全文侧=机构通道（scansci-pdf 类） | q1 实锤不在 OpenAlex |
| **E. 理解错误**（任务级误读） | 两代规划器同一方向错；一切机械修复无效 | 复述自查 + isolated 信号 | 只能升级：向用户确认意图后重规划 | q5 languages→quantization |
| **F. 无反馈长操作**（MCP 侧） | 调用方超时杀进程，后台任务陪葬 | curl 直连 vs 工具链 | 早返回 + 轮询（wait 20s / background:true）；反馈必须比主行动便宜 | 本日两次超时，修复后 selftest 绿 |

## 4. 预防性设计原则（闭环四律）

1. **表征先验证，再投资下游**：任何长链路的第一步产物（查询/计划/子目标），
   必须有便宜的对照试验（2-3 个 oracle 探针）才继续。当天教训：1050 条候选
   的"丰富"是假信号，验证成本只需 3 次标题查询。
2. **反馈必须比主行动便宜**：主行动 5 分钟，反馈信号必须秒级——corroboration/
   isolated（查询间 Jaccard）、饱和 Chao1、expand_advice 都是零成本副产物。
   反馈贵了就不会被频繁跑，闭环等于没有。
3. **机制多元，不是源多元**：4 个关键词源共享同一份表征时，一个错词错 4 次；
   真正的冗余是机制维（关键词/标题索引/relevance/引文图/web）。诊断时也按
   机制隔离，不按源隔离。
4. **升级有出口**：机械修复有明确失效边界（E 类），信号系统必须能识别并把
   判断交还给人（isolated → 提示 agent 重拟；决策层低置信 → 强制 uncertain）。

## 5. 文献锚点（池：error-compounding-and-closed-loop-feedback…，60 篇）

- **Furnas et al. 1987**（10.1145/32206.32212）：词汇问题的奠基实证——两人独立
  选词重合率 10-20%，单查询结构性注定漏 ⇒ 表征必须多元
- **MAST: Why Do Multi-Agent LLM Systems Fail?**（10.52202/085713-4082）：
  失败分类学先例——本模板第 3 节的同构做法
- **DeFA**：依赖引导的失败归因——把"因果距离"变成显式的失败传播图
- **LongRCA Bench**：长程轨迹根因定位基准——根因中位数超前 48 步、最强基线
  13.2% ⇒ 因果距离是硬问题，需要结构化归因而非肉眼看日志
- **Reflexion / Re-ReST / Self-RAG**：言语反馈闭环 / 检索-批评内联验证的
  fix 家族对应物
- **QPP with Minimal Relevance Feedback**（2013）：用极小反馈预测查询失败
  ——corroboration 信号的谱系
- **PRF/局部分析谱系 + PRF 失败审计**：从结果买词（pivot）及其漂移护栏

## 6. 本模板的局限

- 病因分类基于 10 个标本（试点级）；E 类的识别至今没有机械判别法
- 消融的 ladder 臂是单模型单温度，换模型表现会漂
- 模板假设"最终可验证"（有 gold/审计/用户）；开放式任务里 A/B 类的边界会更模糊
- 修复有效性以召回衡量；未测精度代价（pivot 查询可能带入噪声——护栏是席位+佐证机制）
