# 使用示例：一篇硕士开题的文献基础

这是一次真实的完整用法。目标：为玻璃盒机器学习方向的内容准备开题文献。

## 用户做了什么

把一些参考论文交给Deepseek Harness，让它按照citlens中的规则完成该研究领域的文献综述：

1. agent 把每个方向拆成概念块、拟好英文检索词，调 `search`——共跑了
   **11 个子题**；
2. 池子按主题累积在数据目录，跨会话可续用；
3. 逐篇判断相关性后，`fetch` 抓取开放获取全文；
4. 最后按方向汇成文献库、生成引用建议。

## 拿到了什么

完整产物就在本目录的 [artifacts/](artifacts/) 里，可以逐个打开看：

```
artifacts/
├── 文献库分类索引与引用建议.docx  主交付物：总账、8 个主题组的引用理由、
│                                  按方向的引用建议（另有同名 .md）
├── manifest.jsonl                 1072 条总账（每篇带来源与状态）
├── exclusions.jsonl               30 条显式排除（带原因）
├── coverage_audit.json            覆盖审计：1096 条的池对 131 个锚点文献
├── paid_access_channels.md        没拿到全文的 736 条，逐条给出获取渠道
├── by-direction/D1…D9/            9 个方向：阅读清单 + papers.jsonl + 说明
└── run-example/                   一次检索的原始产物（报告 + 池 + 排除日志）
```

几个数字：**364** 篇 PDF 全文、**362** 篇提取正文（本仓库未收录 PDF）、
9 个方向、11 次检索子题。

本目录的解读样例：

| 文件 | 是什么 |
|---|---|
| [sample-search-report.md](sample-search-report.md) | `search` 一次检索的报告（现行版输出格式） |
| [sample-reading-list.md](sample-reading-list.md) | 一个方向的阅读清单（毕设真实产物，节选） |

## 两句实话

- 清单里能看到个别字面撞词的条目（比如讲"可解释机器学习"撞进来一篇
  fitbit 数据论文）——多路召回保证广度，逐篇终审是 agent 和你的活，
  工具不替你判断。
- 毕设检索跑于 2026-10 中旬的早期版本（报告里的家族名称与现行版不同）；
  检索报告样例取自现行版的一次真实运行，仅示格式。
